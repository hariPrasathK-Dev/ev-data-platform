================================================================================
1. INTRODUCTION
================================================================================

Electric vehicles (EVs) represent a critical component of the global transition toward sustainable transportation. As EV adoption accelerates worldwide, the availability and reliability of charging infrastructure has emerged as a key factor influencing consumer confidence and widespread adoption. Understanding charging station utilization patterns, operational reliability, and environmental factors affecting usage is essential for optimizing infrastructure investment and improving user experience.

This project applies Big Data technologies—specifically Hadoop MapReduce and Apache Hive—to analyze a comprehensive real-world dataset of 1,317,750 EV charging station records. The dataset captures detailed information about charging sessions, including station identifiers, timestamps, utilization rates, weather conditions, user demographics, energy consumption, and operational metrics across multiple charging networks.

PROJECT SCOPE:

The analysis addresses three critical dimensions of EV charging infrastructure:

1. Station Utilization Analysis: Identifying high-demand stations, peak usage hours, and capacity bottlenecks to guide infrastructure expansion decisions.

2. Weather Impact Analysis: Quantifying how environmental conditions (temperature, humidity, precipitation) affect charging demand patterns and energy consumption.

3. Station Reliability Analysis: Evaluating operational performance metrics such as uptime, failure rates, and maintenance requirements across different charging networks.

TECHNICAL APPROACH:

The project implements an end-to-end Big Data pipeline:
- Data preprocessing and quality validation using Python
- Distributed storage using Hadoop Distributed File System (HDFS)
- Custom MapReduce programs in Java for parallel processing
- SQL-based analytics using Apache Hive for ad-hoc querying
- Web-based dashboard for visualization and monitoring

SIGNIFICANCE:

This analysis provides actionable insights for multiple stakeholders: charging network operators can optimize maintenance schedules and capacity planning, city planners can make data-driven infrastructure investment decisions, and EV drivers benefit from improved service reliability. By processing over 1.3 million records, the system demonstrates the scalability and effectiveness of distributed computing technologies for solving real-world infrastructure challenges.

5. ARCHITECTURE
================================================================================

SYSTEM ARCHITECTURE:

The system follows a layered architecture for big data processing:

LAYER 1: DATA INGESTION AND PREPROCESSING
- Raw CSV dataset (323 MB, 1.3M+ records)
- Python-based data cleaning and validation
- Output: Cleaned dataset ready for distributed processing

LAYER 2: DISTRIBUTED STORAGE (HDFS)
- Hadoop Distributed File System (HDFS) Version 3.3.1
- NameNode: Manages file system metadata
- DataNode: Stores actual data blocks
- Block Size: 128 MB
- Replication Factor: 1
- Storage Location: /input/ev_charging_station_data_cleaned.csv

LAYER 3: RESOURCE MANAGEMENT (YARN)
- YARN ResourceManager: Manages cluster resources
- YARN NodeManager: Executes tasks on compute nodes
- Application Master: Coordinates MapReduce job execution
- Web UI: http://localhost:8088

LAYER 4: PROCESSING ENGINES
MapReduce Framework:
- Hadoop MapReduce 3.3.1
- Language: Java 8
- Three analytical programs implemented
- Parallel processing of 1.3M records

Apache Hive:
- Version: 3.1.3
- Metastore: Apache Derby (embedded database)
- Query Language: HiveQL (SQL-like)
- Table Format: External table with CSV format

LAYER 5: APPLICATION LAYER
- Backend API: FastAPI (Python 3.12)
- Frontend Dashboard: SvelteKit
- API Endpoints: REST API for HDFS, MapReduce, and Hive operations
- Real-time monitoring and analytics visualization

DEPLOYMENT ENVIRONMENT:
- Operating System: WSL2 Ubuntu 24.04
- Hadoop Home: /usr/local/hadoop
- Hive Home: /usr/local/hive
- Java: OpenJDK 8
- Python: 3.12.x
- Node.js: 20.20.2

DATA FLOW:
1. Raw CSV Data → Data Preprocessing → Cleaned Dataset
2. Cleaned Dataset → HDFS Upload → Distributed Storage
3. HDFS Data → MapReduce/Hive → Processing and Analytics
4. Results → HDFS Output/Hive Tables → Insights Generation
5. API Layer → Web Dashboard → User Visualization

7. MAPPER LOGIC EXPLANATION
================================================================================

PROGRAM 1: STATION UTILIZATION ANALYSIS MAPPER

Input: CSV line with 33 comma-separated fields
Output: Key="Network,Hour", Value="utilization,waitTime,duration"

Mapper Processing Steps:
1. Parse input line by splitting on comma
2. Skip if header row
3. Extract network, hour_of_day, utilization_rate, wait_time, session_duration
4. Validate utilization_rate (must be 0.0 to 1.0)
5. Create composite key combining network and hour
6. Package metrics into value string
7. Emit key-value pair for reducer

PROGRAM 2: WEATHER IMPACT ANALYSIS MAPPER

Input: CSV line
Output: Key="WeatherCondition", Value="utilization,temperature"

Mapper Processing Steps:
1. Parse input line
2. Skip header
3. Extract weather_condition, utilization_rate, temperature_f
4. Validate data fields
5. Emit weather condition as key
6. Package utilization and temperature as value

PROGRAM 3: STATION RELIABILITY ANALYSIS MAPPER

Input: CSV line
Output: Key="StationID|StationName|Network", Value="status"

Mapper Processing Steps:
1. Parse input line
2. Skip header
3. Extract station_id, station_name, network, station_status
4. Create pipe-separated composite key
5. Emit status as value
6. All records for same station go to same reducer

9. REDUCER LOGIC EXPLANATION
================================================================================

PROGRAM 1: STATION UTILIZATION ANALYSIS REDUCER

Input: Key="Network,Hour", Values=Iterator of "util,wait,duration" strings
Output: Key="Network,Hour", Value=Aggregated statistics

Reducer Processing Steps:
1. Initialize counters: count=0, sums for each metric
2. Initialize min/max trackers for utilization
3. Iterate through all values for the key
4. Parse each value and extract metrics
5. Accumulate sums and update min/max
6. Calculate averages: avg = sum / count
7. Format output string with all statistics
8. Emit final aggregated result

PROGRAM 2: WEATHER IMPACT ANALYSIS REDUCER

Input: Key="WeatherCondition", Values=Iterator of "utilization,temperature"
Output: Key="WeatherCondition", Value=Aggregated weather statistics

Reducer Processing Steps:
1. Initialize count and sum variables
2. Track min and max utilization
3. Iterate through all weather observations
4. Accumulate utilization and temperature sums
5. Calculate averages
6. Format output with observation count and metrics
7. Emit weather impact summary

PROGRAM 3: STATION RELIABILITY ANALYSIS REDUCER

Input: Key="StationID|Name|Network", Values=Iterator of status strings
Output: Key="StationID|Name|Network", Value=Reliability metrics

Reducer Processing Steps:
1. Initialize counters for each status type
2. Count total observations
3. Iterate through all status values
4. Increment appropriate status counter
5. Calculate uptime percentage = (operational / total) × 100
6. Calculate downtime percentage
7. Format output with all counts and percentages
8. Emit reliability summary


================================================================================
10. REDUCER CODE
================================================================================

Key reducer code sections for each program:

PROGRAM 1: UTILIZATION REDUCER

The reducer aggregates utilization metrics for each network-hour combination:

- Iterates through all values for a given network-hour key
- Accumulates session counts and metric sums
- Tracks minimum and maximum utilization rates
- Calculates average utilization, wait time, and session duration
- Formats output with all computed statistics
- Output format: "count sessions, avg_util, avg_wait, avg_session, min_util, max_util"

PROGRAM 2: WEATHER REDUCER

The reducer calculates weather impact statistics:

- Processes all observations for each weather condition
- Sums utilization rates and temperatures
- Counts total observations
- Tracks utilization min/max values
- Calculates averages
- Output format: "observations, avg_util, avg_temp, min_util, max_util"

PROGRAM 3: RELIABILITY REDUCER

The reducer computes station reliability metrics:

- Counts occurrences of each status type
- Tracks operational, offline, maintenance, and partial outage counts
- Calculates total observations
- Computes uptime and downtime percentages
- Output format: "total,operational,offline,maintenance,partial_outage,uptime%,downtime%"

15. EACH QUERY EXECUTION
================================================================================

HIVE TABLE CREATION:

Command: hive -f create_table.hql

Table: ev_charging_stations
Records Loaded: 1,317,750
Load Time: 88 seconds

Verification: SELECT COUNT(*) FROM ev_charging_stations;

[SCREENSHOT: Table creation output]

---

QUERY 1: Peak Utilization Hours

SQL:
SELECT hour_of_day, AVG(utilization_rate) AS avg_utilization, COUNT(*) AS observations
FROM ev_charging_stations
WHERE station_status = 'operational'
GROUP BY hour_of_day
ORDER BY avg_utilization DESC
LIMIT 10;

Operators: SELECT, AVG, COUNT, WHERE, GROUP BY, ORDER BY, LIMIT
Time Taken: ~45 seconds

[SCREENSHOT: Query 1 execution and results]

---

QUERY 2: Network Performance Comparison

SQL:
SELECT network, COUNT(*) AS total_observations,
ROUND(SUM(CASE WHEN station_status = 'operational' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2) AS uptime_percentage
FROM ev_charging_stations
GROUP BY network
ORDER BY uptime_percentage DESC;

Operators: SELECT, COUNT, SUM, CASE WHEN, ROUND, GROUP BY, ORDER BY
Time Taken: ~52 seconds

[SCREENSHOT: Query 2 execution and results]

---

QUERY 3: High-Demand Stations

SQL:
SELECT station_id, city, state, AVG(utilization_rate) AS avg_utilization
FROM ev_charging_stations
WHERE station_status = 'operational'
GROUP BY station_id, city, state
HAVING AVG(utilization_rate) > 0.70
ORDER BY avg_utilization DESC
LIMIT 15;

Operators: SELECT, AVG, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT
Time Taken: ~48 seconds

[SCREENSHOT: Query 3 execution and results]

---

QUERY 4: Weekend vs Weekday Demand

SQL:
SELECT CASE WHEN is_weekend = TRUE THEN 'Weekend' ELSE 'Weekday' END AS day_type,
AVG(utilization_rate) AS avg_utilization, COUNT(*) AS total_observations
FROM ev_charging_stations
WHERE station_status = 'operational'
GROUP BY is_weekend
ORDER BY avg_utilization DESC;

Operators: SELECT, CASE WHEN, AVG, COUNT, WHERE, GROUP BY, ORDER BY
Time Taken: ~43 seconds

[SCREENSHOT: Query 4 execution and results]

---

QUERY 5: Weather Impact Analysis

SQL:
SELECT weather_condition, COUNT(*) AS observations,
AVG(utilization_rate) AS avg_utilization, AVG(temperature_f) AS avg_temperature
FROM ev_charging_stations
WHERE station_status = 'operational'
GROUP BY weather_condition
ORDER BY avg_utilization DESC;

Operators: SELECT, COUNT, AVG, WHERE, GROUP BY, ORDER BY
Time Taken: ~41 seconds

[SCREENSHOT: Query 5 execution and results]

Queries 6-15 follow similar patterns using combinations of SELECT, WHERE, GROUP BY, HAVING, ORDER BY, and aggregate functions (COUNT, SUM, AVG, MAX, MIN).

All 15 queries executed successfully with average execution time of 44 seconds.
